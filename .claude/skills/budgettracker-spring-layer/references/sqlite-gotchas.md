# SQLite Gotchas with Spring Boot / Hibernate / Flyway

This file covers the non-obvious differences when running a Spring Boot + Hibernate + Flyway
stack against SQLite instead of PostgreSQL.

---

## UUIDs

SQLite has no native UUID type. Store as `TEXT`.

```sql
-- Migration:
id TEXT PRIMARY KEY   -- correct
id UUID PRIMARY KEY   -- WRONG — SQLite ignores type names but Hibernate may mismap
```

In Java, annotate the entity field normally:
```java
@Id
@GeneratedValue(strategy = GenerationType.UUID)
private UUID id;
```

Hibernate will convert to/from `TEXT` automatically when configured with the SQLite dialect.

**Never** use `DEFAULT gen_random_uuid()` in migrations — SQLite doesn't have this function.
UUIDs are generated by Java before insert.

---

## Timestamps

SQLite has no `TIMESTAMPTZ` or `TIMESTAMP WITH TIME ZONE`. Use `TEXT` and store ISO-8601 UTC.

```sql
-- Migration:
created_at TEXT NOT NULL   -- correct
created_at TIMESTAMPTZ     -- WRONG — SQLite treats this as TEXT anyway, but Hibernate may fail
```

Hibernate with `@CreationTimestamp` / `@UpdateTimestamp` on `Instant` fields will store
correctly as ISO-8601 strings.

## ALTER TABLE Limitations

SQLite's `ALTER TABLE` only supports:
- `ADD COLUMN` (with restrictions — no `NOT NULL` without a `DEFAULT`, no `UNIQUE`)
- `RENAME TABLE`
- `RENAME COLUMN` (SQLite 3.25+)

**Cannot do in SQLite ALTER TABLE:**
- `DROP COLUMN` (before SQLite 3.35)
- `ADD CONSTRAINT`
- `MODIFY COLUMN` / `CHANGE COLUMN`

To restructure a table in a migration, use the copy-and-rename pattern:
```sql
-- 1. Create new table with desired schema
CREATE TABLE transactions_new (...);
-- 2. Copy data
INSERT INTO transactions_new SELECT ... FROM transactions;
-- 3. Drop old table
DROP TABLE transactions;
-- 4. Rename new table
ALTER TABLE transactions_new RENAME TO transactions;
```

## CHECK Constraints

`CHECK` constraints must be defined inline in `CREATE TABLE`. You cannot add them via
`ALTER TABLE ADD CONSTRAINT`.

```sql
-- Correct (in CREATE TABLE):
amount NUMERIC(12,2) NOT NULL CHECK (amount > 0)

-- Will FAIL in SQLite:
ALTER TABLE transactions ADD CONSTRAINT chk_amount CHECK (amount > 0);
```

## Booleans

No native `BOOLEAN` type. Use `INTEGER` with values `0` (false) and `1` (true).

```sql
is_active INTEGER NOT NULL DEFAULT 1
```

In Java, annotate with `@Column(columnDefinition = "INTEGER")` if Hibernate infers wrong type.

---

## Numeric / Decimal

SQLite stores `NUMERIC(12,2)` as a flexible type (it's actually `NUMERIC` affinity). Values are
stored correctly as long as Java uses `BigDecimal`. Never use `double` or `float` for monetary
amounts — floating-point rounding will corrupt values.

---

## FOREIGN KEY Enforcement

SQLite does **not** enforce foreign keys by default. You must enable them per-connection:

```sql
PRAGMA foreign_keys = ON;
```

Add this to your Spring Boot datasource configuration. Without it, `ON DELETE CASCADE` and other
FK constraints are silently ignored.

In `application.properties` or via a `@Bean DataSource` customizer:
```properties
spring.datasource.url=jdbc:sqlite:./budgettracker.db?foreign_keys=on
```

Or with a connection initializer:
```java
@Bean
public DataSourceInitializer dataSourceInitializer(DataSource dataSource) {
    // Run "PRAGMA foreign_keys = ON" after each connection is established
}
```

## Flyway SQLite Dialect

Flyway needs the SQLite JDBC driver and correct dialect config:

```properties
spring.flyway.url=${spring.datasource.url}
spring.flyway.locations=classpath:db/migration
```

Flyway's schema history table (`flyway_schema_history`) is created automatically.
SQLite community edition supports Flyway — no additional config needed beyond the driver.

---

## Hibernate Dialect

Use the community SQLite dialect (not built into Hibernate by default):

```xml
<!-- pom.xml / build.gradle -->
<dependency>
  <groupId>org.xerial</groupId>
  <artifactId>sqlite-jdbc</artifactId>
</dependency>
<dependency>
  <groupId>org.hibernate.orm</groupId>
  <artifactId>hibernate-community-dialects</artifactId>
</dependency>
```

```properties
spring.jpa.database-platform=org.hibernate.community.dialect.SQLiteDialect
```

## Concurrency / WAL Mode

SQLite is single-writer by default. For local dev this is fine. If you see locking errors
under concurrent requests, enable WAL mode:

```sql
PRAGMA journal_mode=WAL;
```

This can be added to the datasource URL or run as a startup script. WAL allows concurrent
reads alongside a single write, which is sufficient for the BudgetTracker workload.
